平台法律责任 · 我们怎么设计

客户出事,责任在谁?平台、provider,还是用户自己?——以及我们如何把敞口降到最低。
FUNWILD · LIABILITY BY DESIGN · YEAR-1 草案

核心定位把自己钉在「信息中介」一侧

整个法律策略只有一句话:尽量留在「信息中介」一侧,远离「组织者 / 背书者 / 安排者」。每个产品和商业决策都用这把标尺量——它在把我们往左推(责任低)还是往右推(责任高)。

纯信息中介
责任低 组织者 / 背书者 / 安排者
责任高 Funwild 目标位置

先拆一个误区「不向用户收费 ≠ 用户自负」

最危险的直觉是:"我们没收用户的钱,所以他们自己约、自己出事。"这个抗辩基本无效。

  • 侵权责任不需要合同,也不需要付费。用户告平台走的是侵权,只要有"过错+因果",免费照样担责。
  • 我们不是慈善。向 provider 收年费 = 营利经营,法院不会当公益论坛看。
  • 免费平台担责的例子到处都是。"免费"不是护身符。

直接回答三个问题

Q1 · 出事能甩给 provider 吗?
能甩一部分——前提是我们真是中介、协议写清用户与 provider 直接缔约。但只要做了背书/认证/推荐,就甩不干净,会和 provider 各担其责。
Q2 · 不收费所以是用户自己的事?
否。见上面的误区。别依赖这个抗辩。
Q3 · 认证教练会让平台担责吗?
会,而且这是最大的自找风险。打"认证"标 = 向用户做了"我把关过"的陈述 → 用户信赖 → 出事 → 可能构成过失虚假陈述 / 自愿承担的注意义务(德 Garantenstellung)/ 触发中国《电商法》第38条对生命健康类服务的资质审核+安全保障义务(可达连带)。

三个结构性决策已定,且互相加固

决策选择法律作用
实体中国实体(小程序备案/国内)+ 德国 GmbH(欧洲经营)责任隔离;出事被告的是有限责任+投保的德国壳
资金完全不碰交易资金;仅收 provider 年费强化中介地位;避开支付牌照、反洗钱、托管担保责任
地接Year-1 仅引流,provider 自己成交,不在平台打包下单避开欧盟一揽子旅游指令的"组织者严格责任 + 强制破产保障金"

三者是同一个哲学:轻中介。做完这三个,Year-1 法律上最大的、且是自找的敞口,就只剩"认证"标这一个产品问题——而它已经改掉了(见下)。

认证标的重构从「背书」收窄为「事实陈述」

这是唯一一个我们自己往"背书者"方向拉的产品决策,已修复:

✗ 改之前

✓ Funwild 认证

含义模糊,像在担保"这个人靠谱/安全"。一旦出事,等于平台为其能力背书。

✓ 改之后

✓ 身份已核验 ✓ 资质已核验

只陈述客观事实:"我们核对了身份/资质文件真实存在"。可证明、可辩护,不担保水平与安全结果。配免责说明。

关键区别:"我们查验过他持有 X 证书"(事实)vs "Funwild 认证教练"(隐含能力/安全担保)。法律上天差地别。

安全功能 = 法律资产

我们做的安全确认清单不只是 UX——它是少数"产品功能直接降低法律风险"的例子:它记录了"用户被告知风险并确认知情"。建议野雪/高风险场景的勾选带时间戳留存,作为知情同意(informed consent)的抗辩证据。安全知识内容也一样:框定为"教育科普、非专业指导、以官方公告为准",则利大于弊。

缓解清单跨业务的通用动作

  • 德国 GmbH 作欧洲经营/担责主体 + 中国实体管小程序备案
  • 平台层保险(一般责任/D&O/内容) + 强制 provider 职业责任险(入驻校验)
  • 维持"完全不碰钱";慎加任何担保交易/托管功能
  • 用户协议 + provider 入驻协议(中介定位/责任划分/赔偿/适用法)
  • 信任标只做事实陈述(已做) + 全程避免"推荐/担保"措辞
  • 安全确认勾选带时间戳存档
  • DSA(通知-移除/举报) + PIPL/GDPR 双合规(跨境数据)
  • 安全/攻略内容统一免责声明

待律师拍板

  • 德国 GmbH 是否足够,还是需要旅游/中介牌照?
  • "撮合野雪私教"在中国电商法38条下是否仍触发连带?如何最小化?
  • "仅引流"地接的页面措辞/跳转,如何稳稳落在"非组织者/非 LTA"?
  • 拼车"成本分摊"在德/奥/瑞的安全边界(每公里上限?)
  • "已核验"措辞在 UWG/消费者法下是否仍有误导风险?
  • 中国用户在何情形能在中国起诉德国 GmbH?管辖与执行?
  • 平台层 + provider 层的最低保额与险种组合
