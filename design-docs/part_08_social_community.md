# Part 8 · 社交与社区机制 · Social & Community Mechanics

> 4 大社交机制 · 用户为什么留下 · viral growth 引擎 · 不做"动态流"

---

## 0. 总原则

### 0.1 核心命题

> **用户的 social capital 是他留在 Funwild 的最大理由。**

- "好用"是必要条件，但不充分（雪搭子也好用）
- "我在这里有别人看得见的存在感"才是离不开的理由

### 0.2 4 大社交机制（按重要性）

| # | 机制 | 价值 |
|---|---|---|
| M1 | 徽章系统 | 个人 identity + retention |
| M2 | 海报体系 | viral growth |
| M3 | 拼车关系链 + 关注 | network effect |
| M4 | 隐性 UGC（行为副产品） | 信息流但低 friction |

### 0.3 不做的事

- ❌ 不做"动态信息流 / 瀑布流"（用户不"发动态"）
- ❌ 不做"加好友"二元关系（高 friction，关注即可）
- ❌ 不做"评分排行榜"（破坏 hardcore 氛围）
- ❌ 不做"内容社区" / "兴趣圈子"（产能不够）

## 1. M1 · 徽章系统（最重要）

### 1.1 角色

- **个人 identity**：用户主页大字主徽章 = "我是谁"
- **retention engine**：即将解锁 nudge = 下次回来的理由
- **viral**：解锁海报 = 朋友圈分享

### 1.2 142 徽章的分组逻辑（已在 BP V7）

| 类 | 数量 | 角色 |
|---|---|---|
| 身份类 | 12 | onboarding + 状态 |
| 雪场探索类 | 19 | 打卡里程碑 |
| 社交类 | 13 | 关系网络 |
| 内容贡献类 | 10 | UGC |
| 活动类 | 13 | 参与 |
| 教练专属 | 10 | 教练职业 |
| 成就类 | 13 | 综合 |
| 趣味彩蛋类 | 18 | 生活方式 |
| 神秘隐藏类 | 14 | 探索 |
| 彩蛋预告类 | 8 | Year 2+ 扩展 |
| 平台生态类 | 12 | 商业循环 |

### 1.3 徽章设计原则

| 原则 | 实现 |
|---|---|
| **可达性梯度** | 80% 徽章普通用户能拿，20% 需努力 |
| **稀缺感** | 神秘 / 限时徽章 < 1% 用户解锁 |
| **可视化天花板高** | 142 SVG 已有视觉资产，质量可控 |
| **解锁瞬间仪式感** | 弹窗 + 海报 + 下一枚预告 |
| **解锁条件简单可懂** | "Stubaier 打卡 3 次" 而非"复杂积分制" |
| **可分享** | 默认带海报模板 |

### 1.4 三态视觉（设计师补足）

| 态 | 视觉 |
|---|---|
| 彩色 已解锁 | 142 SVG 原色 |
| 灰色 未解锁 | CSS `grayscale(1) opacity(0.4)` 派生 |
| 50% 进度 灰 + 环 | SVG `stroke-dasharray` 环绕徽章 |

### 1.5 即将解锁 Nudge 算法（详见 13_badge_wall）

排序优先级：
1. 差 1 步即可解锁
2. 进度 80%+
3. 雪季内可达
4. 当前位置相关

→ 每个 nudge 配 1 个可执行的下一步动作。

### 1.6 隐藏徽章的传播效应

- 徽章墙显示 "???"  
- 用户在群里问"我看到 ??? 是什么徽章" → 自然传播
- 隐藏徽章名 + 解锁条件应该有"梗"价值
  - 例："情人节雪友" = 情人节去雪场
  - 例："鸽子王" = 临时取消 5 次
  - 例："11 月 1 日" = 平台上线日打卡

### 1.7 Year 1 上线节奏

| 阶段 | 上线徽章数 | 设计师产能 |
|---|---|---|
| V1.0（11 月） | 50 个 | 25 + AI 半自动 25 |
| V1.1（1 月） | 80 个 | + 30 |
| V1.2（3 月） | 100 个 | + 20 |
| V1.3（5 月） | 142 个 | + 42（雪季后慢慢补） |

## 2. M2 · 海报体系（viral 主引擎）

### 2.1 角色

> **让用户分享出去就是品牌曝光。**

不是邀请码、不是裂变红包。让分享物本身**好看到不舍得删**。

### 2.2 4 类海报模板

| 模板 | 触发 | 内容元素 |
|---|---|---|
| **打卡海报** | 雪场打卡 | 雪场 hero 图 + 用户头像 + 打卡数 + 二维码 |
| **徽章海报** | 解锁徽章 | 大徽章 + 用户头像 + 解锁日期 + 二维码 |
| **拼车海报** | 发布拼车 | 雪场图 + 日期 + 还差 X 位 + 二维码 |
| **评价海报** | 写评价 | 教练头像 + 评价摘录 + 用户头像 + 二维码 |

### 2.3 海报视觉构成

```
┌─────────────────────────────────────┐
│  [真实雪场照片 全屏背景]              │ ← 雪场提供高清照片库
│                                     │
│       [大头像 90×90 圆]              │ ← 用户头像
│                                     │
│       张小美                         │
│       Stubaier 第 12 次              │
│                                     │
│       [大徽章 / 主体内容]            │
│                                     │
│                                     │
│                                     │
│  [Funwild logo 小]   [二维码 80×80]  │ ← 底部固定
│  趣野                趣野 Funwild     │
└─────────────────────────────────────┘
```

### 2.4 海报视觉原则

- **不让用户写文案**（写文案的 friction 太高）
- **不放过多 logo / 水印**（破坏画面）
- **背景必须是真实雪山照**（不是渐变色）
- **底部 logo + 二维码尺寸克制**（不抢戏）
- **生成速度 < 3 秒**（服务端 canvas + 队列）

### 2.5 海报分享渠道

| 渠道 | 流量价值 | 干预 |
|---|---|---|
| 微信朋友圈 | 高（决策圈层） | 自动生成 + 一键打开朋友圈 |
| 微信群 | 高（精准） | 海报内文案适配群分享 |
| 小红书 | 高（拉新） | 一键复制内容 + 加 hashtag |
| 抖音 / 视频号 | 中（V1.1） | V1 不主推 |
| 截图发其他平台 | 低 | 用户自行 |

## 3. M3 · 拼车关系链 + 关注（network effect）

### 3.1 核心机制：自动关注推荐

```
拼车成行 + 一周后
  ↓
系统 push："你和 X 一起去过 Spitzingsee，互相关注吗？"
  [关注] [稍后]
  ↓
点 [关注] → 默认双向（X 也收到"想关注你"通知）
```

### 3.2 关注的语义

- **关注** ≠ 加好友（不需要对方同意）
- **关注的人**的动态出现在你的首页"关注的人动态"模块
- **互相关注**才算"雪友关系"，可点对方主页看完整徽章 + 雪场轨迹

### 3.3 不做"加好友"的原因

- 加好友需要对方同意 → 高 friction
- "已关注" / "互相关注" 二态 → 渐进信任
- 互联网产品（小红书 / Strava）已经证明关注 > 好友

### 3.4 关系链的网络效应

```
第 1 周：用户 A 关注 1 人（B）
第 2 周：A 看到 B 的拼车，加入 → 关注 2 人（B + C）
第 3 周：A 看到 C 的活动，报名 → 关注 3 人（B + C + D）
...
第 N 周：A 关注 5-10 人 → 每周首页都有可看的动态
```

→ Year 1 末，活跃用户平均关注 5-10 人 → network 形成。

### 3.5 关注的反向价值（拉新）

- 用户 A 关注 B 后，B 收到 "A 关注了你"
- B 增加被关注计数 → 满足感
- B 倾向于多发拼车 / 多打卡 → 让 A 看到
- → 关注让被关注者更活跃

## 4. M4 · 隐性 UGC（行为副产品）

### 4.1 核心命题

> **用户从不"发动态"，但他的关注者每周都能看到他的活动。**

### 4.2 自动生成的"动态"

| 动作 | 自动动态 |
|---|---|
| 打卡雪场 | "X 打卡了 Stubaier · 第 12 次" |
| 报名活动 | "X 报名了 Camp Good Times" |
| 解锁徽章 | "X 解锁了 'Stubaier 三连' 徽章" |
| 写评价 | "X 评价了张磊教练 · 5 星" |
| 发布攻略 | "X 发布了 '阿尔卑斯首滑全攻略'" |
| 发布拼车 | "X 发布了周六 Stubaier 拼车计划" |

### 4.3 这些动态出现在哪

- 用户公开主页（V1.1）：完整 timeline
- 关注者的首页"关注的人动态"模块（V1.1）
- 雪场详情页"最近打卡"模块
- 教练页"最新评价"模块
- 活动页"已报名头像 list"模块

### 4.4 与"内容社区"的本质区别

| 内容社区（小红书 / 抖音） | Funwild 隐性 UGC |
|---|---|
| 用户主动发布 | 用户行为自动生成 |
| 内容质量参差 | 内容标准统一（系统模板） |
| 需要算法分发 | 关注关系自动分发 |
| 创作者激励池 | 用户自然行为不需要激励 |
| 内容审核 | 行为本身即审核（来自真实操作） |

→ Funwild 的"信息流"是行为的副产品，不是 UGC 平台。

## 5. 评价系统

### 5.1 双源评价

| 来源 | 标签 | 限制 |
|---|---|---|
| **平台撮合订单** | "Funwild 撮合" | 自动开放写评价权限 |
| **教练手动添加老学员** | "老学员" | 需要被评学员在平台确认 |

### 5.2 评价显示

- 教练详情页 / 地接详情页：所有评价聚合
- 用户主页：用户的"被评价"timeline
- 评分以"平台撮合"为主权重，"老学员"参考

### 5.3 防刷防恶意

- 教练 / 地接不能给用户打评价（避免反向施压）
- 同一用户 30 天内不能写多条同一教练评价
- 评价 < 5 个的教练 / 地接不显示总评分（避免单条恶意打 1 星）

## 7. 社交 friction 与权衡

### 7.1 隐私默认值

V1 默认值：

| 维度 | 默认 |
|---|---|
| 雪场打卡历史 | 关注者可见 |
| 徽章墙 | 关注者可见 |
| 公开主页（V1.1） | 默认私密，需开启 |
| 真实姓名 | 不公开 |
| 手机号 | 不公开 |

### 7.2 让用户开公开

不做"强制开公开"，但用激励让用户主动开：
- 开公开主页 → 解锁徽章
- 关注数 > 10 自动 hint "你已经很活跃，要开公开主页让更多人看到吗？"

## 10. 为什么用户会留下 · 为什么会流失

### 10.1 留下的理由

1. **social capital 不可迁移**：删账号 = 删一整个雪季的徽章 + 关系
2. **关注的人有更新**：每周首页都有可看的
3. **徽章离 1 步**：永远有"下一个"
4. **打卡是身份**：在雪场遇到戴 Funwild pin 的人 = 同好
5. **评价数据**：教练 / 地接的评价是不可替代的决策资产

### 10.2 流失的理由

1. **关注的人都不活跃**：首页空 → 用户也流失
2. **徽章撞墙**：解锁完所有简单徽章 → 失去 progression
3. **拼车没人组**：周末空 → 不再来
4. **海报视觉过时**：朋友圈不再有人发
5. **平台让人不爽**：教练绕单 + 地接虚假 + 评价被刷

→ 全部 mitigation 措施已在前面机制中。
