# Part 10 · 微信生态约束 · WeChat Constraints

> 10 条硬约束 × 10 条 interaction 解法 · 不试图绕过，而是设计

---

## 0. 总原则

> **微信约束不是"问题"，是"游戏规则"。**

把约束当设计前提，而不是 obstacle。试图绕过微信约束通常**导致小程序被拒 / 被警告**，破坏 Year 1 上线节奏。

---

## 1. 约束表 · 10 条

### C1 · 订阅消息：用户每次单独授权

**约束**：小程序的订阅消息每次只能发 1 条，且需用户在某个 trigger 时点击"允许"。不能群发 push。

**影响**：核心 push（如周三晚拼车推送）需要用户在某次操作时主动订阅。

**Interaction 解法**：
- 每个关键节点单独 ask：
  - 报名活动后 → "订阅活动提醒"
  - 加入拼车后 → "订阅出行通知"
  - 教练 wave 后 → "订阅教练回复"
  - 徽章离 1 步时 → "订阅徽章解锁"
- 每次只问 1 个授权，**不要批量**（用户会拒绝）

---

### C2 · 小程序不能跳外部链接

**约束**：小程序内 `wx.openUrl` 受限，不能直接跳浏览器。

**影响**：Website 跳转、外部资源、品牌方官网链接均无法直接跳。

**Interaction 解法**：
- 改为生成二维码或长按识别 + 引导"截图保存后浏览器打开"
- 教练 / 地接的"个人网站"链接 → 二维码弹层
- "在 Website 查看完整版" → 弹二维码

---

### C3 · 扫码进入小程序需要"识别"步骤

**约束**：从浏览器扫小程序码 → 进入微信 → 长按二维码 → 识别 → 跳小程序，多了 1 步。

**影响**：Journey A 中 Website → 小程序的扫码 friction 增加。

**Interaction 解法**：
- Website 落地页二维码下面显示"扫码进小程序，3 步搞定"
- 教练 / 攻略短链识别方案优化：直接打开微信 → 自动识别（短链协议）
- 提供"复制链接到微信"按钮 → 用户在微信粘贴可直接跳

---

### C4 · 小程序不能默认推送通知

**约束**：用户必须先订阅服务号 / 开启订阅消息，否则收不到任何通知。

**影响**：核心 push（周三晚 / 行前 7 天）很容易丢失。

**Interaction 解法**：
- **三层兜底**：① 微信服务号（关注后宽松 push）② 小程序订阅消息（每次单独授权）③ 站内消息中心（兜底，红点 + 数字）
- onboarding 完成 → 弹"关注 Funwild 服务号？" + 二维码
- 重要消息双轨：服务号 + 站内同时发

---

### C5 · 小程序分享到朋友圈需先生成图片

**约束**：小程序分享按钮在朋友圈受限，必须保存图片到相册再手动发。

**影响**：朋友圈传播 friction 高。

**Interaction 解法**：
- 默认生成海报图片（不是分享链接）
- 一键"保存到相册" + 自动打开朋友圈
- 朋友圈传播的载体是图片，不是链接
- 海报右下角二维码作为回流入口

---

### C6 · `wx.getLocation` 用户每次都要授权

**约束**：位置授权不能 once for all，每次调用都弹授权。

**影响**：打卡 friction 增加（每次都弹）。

**Interaction 解法**：
- 第一次给原因说明："Funwild 用一次位置识别雪场，不会持续追踪"
- 用户允许后 30 分钟内不再弹（用 cached location）
- 雪场 5km 内自动 trigger 打卡 hint，用户点确认即可

---

### C7 · 小程序包大小 < 2MB（主包）

**约束**：主包不能超过 2MB，否则审核不过。

**影响**：18 雪场攻略 + 142 徽章 SVG + 真实图片不能全部内置。

**Interaction 解法**：
- 所有图片走 CDN，懒加载（用户滚到才加载）
- 主包只放 UI 代码 + 必要 placeholder
- 雪场详情图、教练头像、徽章 SVG → 子包按需加载
- 服务端 canvas 生成海报（避免客户端图片库膨胀）

---

### C8 · 不支持站内支付（Year 1）

**约束**：站内支付需要小程序商户号 + 资金合规审核，Year 1 不做。

**影响**：活动报名 / 联系教练 / 联系地接 等场景需要绕过支付。

**Interaction 解法**：
- 活动报名：占位 → 客服私聊 → 微信转账 / 银行转账
- 联系教练：wave → 微信对话 → 教练私下收款
- 联系地接：项目咨询 → 跳到地接微信 → 地接自己收款
- 明确标注"信息撮合，不参与交易"

---

### C9 · 小程序审核风险（涉及交易）

**约束**：明显的电商功能（购物车 / 站内支付 / 物流）会被严格审核，可能被拒。

**影响**：市集 / 地接 marketplace 设计需要小心。

**Interaction 解法**：
- 市集 → "线下交易"明确标注 + 平台不参与
- 地接 → "信息撮合"+"咨询服务商微信"
- 教练 → wave + 私聊
- 用户协议明确"Funwild 是信息平台，不参与交易"

---

### C10 · 群裂变 / 朋友圈广告受限

**约束**：微信对"诱导分享" / "强制裂变"严格限制。"分享得徽章 / 红包"等会被警告。

**影响**：邀请机制 / 拉新动作必须自然。

**Interaction 解法**：
- 邀请码作为身份标识，**不强制**邀请才能用
- 海报里**不强调**"拉新得奖励"
- 让海报视觉本身好看 → 用户自然愿意发
- "邀请徽章"按"已邀请 N 人"统计，**不诱导**"快邀请 X 人"

## 2. Cross-platform 互通的 5 种方式

### 2.1 微信扫码进小程序

最常用，但有 friction（需识别）。优化方向 = Website 落地页 + 短链识别。

### 2.2 微信 deep link（小程序内）

```
微信群消息 → 小程序卡片 → 直接打开特定页面
```

支持 `weixin://dl/business/?t=...` 协议，可携带参数。

### 2.3 小程序内分享到群 / 朋友

通过 `wx.shareAppMessage`，可生成小程序卡片（带封面图 + 标题 + 描述）。

### 2.4 微信服务号 → 小程序

服务号文章 / 推送消息可嵌入小程序卡片，点击直接打开。

### 2.5 二维码识别

最通用但最 friction。仅在 Website / 海报 / 线下场景使用。

## 3. 微信小程序原生能力 · Funwild 用到的 / 不用的

### 3.1 用的

| 能力 | Funwild 用途 |
|---|---|
| `wx.login` | 微信一键登录 |
| `wx.getUserInfo` | 获取头像 + 昵称 |
| `wx.getLocation` | 打卡定位 |
| 订阅消息 | 关键 push（拼车 / 报名 / 教练回复 / 徽章） |
| 客服消息 | 客服对话（V1.1） |
| 分享 / 朋友圈 | 海报传播 |
| `wx.scanCode` | 扫码（招商 / 入驻流程） |
| 客户端缓存 / Storage | 离线攻略 |

### 3.2 不用的

| 能力 | 原因 |
|---|---|
| 微信支付 | Year 2 再做 |
| `wx.uploadFile`（大文件） | 用户头像走 OSS，不直接上传 |
| `wx.startRecord`（录音） | 不需要 |
| 直播 | 不需要 |
| 小程序云开发 | 用自建后端 |
| 微信 WebGL | 不需要 |

## 4. 三方推送方案

### 4.1 微信服务号 vs 订阅消息 vs 站内

| 渠道 | 触达率 | friction | 限制 | 用途 |
|---|---|---|---|---|
| **微信服务号** | 80%（用户关注后） | 用户首次需关注 | 每天最多 1 条群发 | 周三晚拼车推送 |
| **小程序订阅消息** | 95%（用户授权后） | 每次单独授权 | 模板严格 | 报名后 / wave 后等单次事件 |
| **站内消息中心** | 100% | 0 | 用户必须打开小程序才看到 | 兜底 + 行内查看 |

### 4.2 同步策略

同一消息可能同时通过 3 个渠道送达：
- 服务号 push + 小程序订阅 + 站内消息 = 同一 message_id
- 用户在任一渠道点击 / 已读 → 其他渠道自动标已读
- 避免重复打扰

## 5. 小程序原生 UI 推荐使用

为减少 design system 偏差和工程量，**优先使用微信小程序原生组件**：

| 组件 | 使用 |
|---|---|
| `picker` 日期 / 时间选择 | onboarding 出行日期 |
| `picker` 单选 | 雪场选择 / 城市选择 |
| `swiper` 轮播 | 雪场详情封面图 |
| `image` 图片 lazy-load | 列表 |
| `scroll-view` 滚动 | 大列表 |
| `actionsheet` 操作菜单 | 分享 / 删除 |

**自定义 UI**只在视觉差异化重要的场合用（徽章 / 海报 / Hero）。

## 6. 失败案例 · 微信审核被拒常见原因

| 失败原因 | Funwild 防御 |
|---|---|
| 涉及交易但无支付资质 | 明确"信息撮合" + 用户协议 |
| 个人信息收集不透明 | 隐私政策 + onboarding 说明 |
| 诱导分享 | 海报自然 + 不强制裂变 |
| 内容违反法规（黄赌毒） | 内容审核 + 关键词过滤 |
| 截图含外部联系方式（微信号 / 电话） | 用户内容过滤 |
| 引导跳出微信 | 不做 H5 跳转 |
